# AI-assisted development

LLMs were used throughout the project to explain the assignment, generate code
and tests, design the ML-KEM integration, write CI and monitoring configuration,
and review the result. The working rule from the course brief applied to all of
it: generated output is untrusted until it has been read, tested and checked
against the running system.

| Version | Who | Tools | Used for |
|------------|------------------|-----------------------------|-----------------------------------|
| v1.0.0 | Stanislav Řihák, Roland Budzák | ChatGPT (GPT-4o) | understanding the brief, baseline code, versioning plan |
| v2.0.0 | Tom | Codex; Claude Code (Opus coordinating Sonnet agents) | ML-KEM session design, tests, CI/CD |
| v2.1.0 | Stanislav Řihák | Claude Code (Sonnet 4.6; review with Opus 5.5) | metrics, Grafana dashboard, CI suites; end-of-version review |

| v3.1.0 | Tom | Codex (GPT-based agents) | persistence, legacy switch, sensor state, monitoring, CI evidence |
| v3.2.0 | Stanislav Řihák | Claude Code (Opus 5.5) | review of v3, key handling, library change, `NaN` fix |

The prompts, the AI output and the decisions are recorded for every version:
for the rewrite in `documentation/phases/` of the code repository, for v3.1.0 in
`docs/ai/prompts/`, and for the earlier architecture in
`docs/archive/pre-v3/docs/ai/prompts/`.

## Generated artefacts and decisions

| Artefact | Generated by | Decision | Why / what was found |
|---------------------|---------------|-------------|--------------------------------------|
| Baseline services and Compose setup (v1.0.0) | ChatGPT | accepted | Simple, ran first time; reviewed and its weaknesses recorded. |
| ML-KEM in the very first version | ChatGPT | rejected (deferred) | A working plaintext baseline was needed first, as a reference. |
| Session-based ML-KEM channel (v2) | Codex, Claude Code | accepted, later replaced | Worked and was well tested, but a review found nonce reuse after a lost reply, and its size made it hard to review. |
| Crypto metrics and Grafana dashboard (v2.1) | Claude Code | modified | Dashboard did not connect until a fixed data-source ID was added; a review then found counters that counted the wrong thing or never moved. |
| DS18B20 simulation and `NaN` fix (v2.2) | Claude Code | accepted | Tests written first and seen failing. |
| Rewrite, per-message ML-KEM (v3.0) | Claude Code | accepted, later corrected | Readable and correct on the happy path; review found a committed private key, an educational ML-KEM library, missing validation and a 30-second replay window. |
| Recommendation against Grafana in the rewrite | Claude Code | accepted, later reversed | Simplicity first; monitoring with alerts was added back in v3.1 because the brief asks for meaningful operations. |
| Persistence, legacy switch, sensor state, monitoring (v3.1) | Codex | accepted, then corrected | Merged without human review; a later test of the legacy path found that `NaN` was stored and broke every read. |
| Key generation, OpenSSL ML-KEM, `NaN` fix (v3.2) | Claude Code | accepted | Tests first; checked in Docker together with the CI smoke and reliability scripts. |
